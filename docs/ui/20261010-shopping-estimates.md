# Shopping list: category labels, photography and indicative estimates

The old shopping screen used a category translation directly as a heading.
Production catalog categories `condiment`, `spice`, `sweetener` and `beverage`
were missing from localization, so the default `unknown_error` text appeared
as the heading of a successfully loaded list. All six locales now include those
categories. Unknown future groups use Other, consistently in grouping and export.
Actual request errors retain the existing ResourceState retry behavior.

Shopping rows resolve FoodImage using the catalog's exact food ID, image URL and
private photo ID, as Fridge already does. Missing images keep the existing icon
fallback. Neutral square cards use a three-column grid at standard text sizes,
with photography, name, quantity and estimate kept compact. Selection remains
direct; edit, delete and Fridge transfer live in each card's overflow menu.
Checkbox and menu targets remain at least 44 px. The grid adapts to two or one
column when text scaling needs more room. Both themes retain AppShell's navigation
inset, scrolling and mutation logic.

## Estimate assumptions

The user chose generic indicative category references. `category-eur-v1` is a
planning assumption, NOT a sourced current retail price, price feed, forecast,
regional average, or quote. The interface and export explicitly state this.
No payment, cost, nutrition or backend records are changed.

All references are in EUR. They are applied to the required quantity, not rounded
up to whole supermarket packs; this distinction is shown in the summary. Each
square card shows the estimate for its listed quantity; reference €/kg, €/l and
€/piece assumptions remain versioned here. No currency conversion.

Per kg: vegetables 3, fruit 3.50, grains 2.50, legumes 3.50, meat 12, fish 18,
dairy 9, oil 8, nuts 18, seeds 12, herbs 20, eggs 5, honey 12, packaged food 6,
condiments 8, spices 25, sweeteners 4.
Per litre: dairy 1.70, oil 8, condiments 8, honey 16, packaged food/drinks 2.50.
Per piece: eggs 0.40. Other category/unit combinations remain unavailable.

Grams/kg and ml/l convert separately; piece prices are never inferred from mass.
Each line rounds to cents; the grand total adds the displayed line amounts,
including checked lines until they are removed/moved to Fridge. Unknown prices,
unsupported units and invalid quantities are excluded, never treated as zero.
The summary becomes a partial total and shows the number of excluded lines.
Editing/deleting lines reloads quantities and recomputes the estimate.

## Verification

Local Dart formatting, localization contracts (1180 keys in six locales), and
`git diff --check` pass. Local Flutter analyze/widget tests were not executed:
the dependency download was interrupted by the execution environment and the
offline cache cannot resolve the locked dependencies. The existing PR CI runs
analysis and the full tests and uploads interface-review screenshots; results
must be reviewed before merge.

Tests cover unit conversion, per-line rounding, unsupported/invalid input, future
category fallback, check/version mutations, totals, both themes, six locales and
320 px screens at 200% text. Light/dark screenshots are generated by the Flutter
widget test with actual bundled fonts and mock API data. Existing application
shopping tests cover purchase/reconciliation behavior. Screenshots use exact
bundled catalog food images; unsupported photography is not fabricated.
